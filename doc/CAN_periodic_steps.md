# 周期报文列表工步

入口：编辑子工步 → 报文交互 → CAN 交互。

1. 选择“启动周期报文列表”，填写列表名称，例如 BMS唤醒。
2. 添加报文；每行配置 ID（HEX）、数据（HEX）、发送周期（ms）和 Classic / CAN FD / CAN FD + BRS。
3. 选择配方绑定 CAN 卡的物理通道。报文列表启动后立即发一轮，之后按各行周期持续发送，后续测试工步继续执行。
4. 在需要结束的位置添加“停止周期报文列表”，填写完全一致的列表名称。停止按名称查找已启动任务，不依赖停止工步当前显示的通道。

例如：启动 BMS唤醒 → 等待 → 电压读取 → UDS测试 → 停止 BMS唤醒。

保存配方和开始测试均校验实际启用顺序：不允许先停止后启动、重复启动、重复停止或缺少后续停止。被屏蔽或未被选中的启动工步不满足停止工步依赖。列表名称允许重复使用，但前一组必须先停止。

手动停止、NG中止和正常结束会清理周期发送任务，避免跨产品残留。后台发送失败会在后续检查或结束清理时报错；接口变化后原任务停止并报错。停止等待当前已进入驱动的发送调用返回，最长使用两秒等待，超时明确报错。

限制：每列表1～100条，最多同时16个列表；周期10～3600000 ms。ID大于0x7FF自动使用扩展帧。经典CAN最多8字节；CAN FD只接受合法长度，不隐式补长。FD报文要求配方启用FD。Windows线程调度与驱动耗时会影响实际周期，错过的周期不突发补发，不能当作硬实时总线发生器。
