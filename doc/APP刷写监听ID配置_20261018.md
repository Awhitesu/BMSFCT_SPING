# APP刷写进度监听 ID 配置

工步与配方配置 → 编辑 APP刷写工步 → 执行刷写：填写“刷写请求 ID（HEX）”和“刷写响应 ID（HEX）”。支持带/不带0x前缀，按十六进制解释，范围0–0x1FFFFFFF，两个ID不可相同。保存后参数为 FLASH_TX_ID / FLASH_RX_ID，执行引擎传入被动监听器。原有工步没有配置时保持0x7E4/0x7EC兼容默认。

这两个字段控制本软件如何识别外部上位机刷写报文，不修改外部上位机发送的实际ID。必须按项目的真实报文填写，不能依据普通业务报文任意设置。监控收到其他ID数据不代表刷写进度可解析。最终PASS/FAIL仍以Record.txt为准。

普通报文监控与刷写监听共用PCANFDDriver._publish数据源。刷写监听先订阅，再写Start；报文复制给订阅者，不从监控队列中移除数据。弹窗显示总RX数、目标ID和未匹配时已见ID，并将诊断状态每5秒/状态变更/结束写入运行日志，即使不显示弹窗也会记录。监听从本次刷写开始累计，不包含之前的历史报文和本机TX记录。

之前弹窗“尚未收到刷写报文”仅表示未匹配固定ID，不代表PCAN没有任何接收。新文案区分未收到总线报文与有报文但ID未匹配。源码修改不会更新已运行的EXE，需关闭后使用新构建版本。

验证：tests/test_flash_monitor_configuration.py 覆盖ID编辑保存回读、非法ID、普通监控与订阅同时收到同一报文、弹窗未匹配提示；联合刷写进度、弹窗和记录测试日志在 logs/flash_configurable_ids。真实项目ID待操作员填写，无实际刷写验证。

弹窗生命周期：只在刷写进行中显示；APP、SG400、E2 完成、失败或停止后自动隐藏，日志继续保存结果。自动隐藏不视作操作员手动关闭，因此后续刷写工步可以再次弹出。logs/flash_popup_auto_hide 覆盖三类设备的三种终态、下一个刷写工步弹出和手动停止隐藏。
