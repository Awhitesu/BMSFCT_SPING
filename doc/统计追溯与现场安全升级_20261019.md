# 统计追溯与现场安全升级

## 按项目累计统计

良率按当前选中的配方项目分别累计，从该项目上次手动清零之后一直延续，不使用日期或班次筛选。切换项目自动带出该项目的总数、合格数、不合格数和良率；跨天、重启不清零。未选择项目时不显示其他项目的累计结果。界面已删除时间范围说明，设置页只保留“项目统计详情”。

在统计卡片上悬停可查看项目及当前数据库路径。不同软件目录中的数据库仍然独立；不要把新版本目录中的初始数据库当成现场数据库。

数据库新增 `statistics_audit` 表记录追溯，`project_statistics_state` 保存各项目独立的清零起点。记录包含项目、操作用户、时间、数据库路径、清零及变化前后的数量。清零成功记录和清零起点在同一事务中提交，失败一起回滚。只清零当前项目，不影响其他项目，也不删除原始记录。旧版已手动清零的边界会被保留，避免升级后恢复此前清掉的统计。

项目身份由数据库 `project_identity` 中的稳定编号关联，测试记录保存 `project_id`。通过软件改名时，项目编号及清零起点不变，历史测试记录仍保留测试当时的名称。旧记录会在首次查询或改名时关联编号。另存为其他配方是独立项目；改名后重新使用旧名称创建的项目也不会混入原项目历史。请通过软件改名，直接在资源管理器中修改文件名不属于这个迁移流程。

## 扫码匹配与在线抓取保护

扫码配方匹配在后台进行，使用有超时能力的 regex 库。单条规则最多匹配50毫秒，一次匹配总预算2秒；规则错误、超时及多配方匹配均不会自动加载。匹配期间配方列表或账户变化会使旧结果失效。超时接口参见 [regex 官方说明](https://pypi.org/project/regex/)。

CAN及UDS在线抓取会记录设备连接、通道、请求/响应ID及帧参数。等待期间修改这些参数后，旧回复不会覆盖当前解析样例，需要重新抓取。

该追溯只能解释安装此改动之后的变化，不能补回旧版本没有记录的现场原因。发现统计异常时保留现场数据库及日志。

## 现有工位升级

下次打包会自动附带 `upgrade_app.cmd` 和 `upgrade_app.ps1`。

1. 退出现场旧软件和相关辅助进程，也不要启动新版。
2. 解压完整新版到另一个目录。
3. 在新版目录双击 `upgrade_app.cmd`，输入原来一直使用的软件文件夹路径。
4. 工具检查新版主程序校验值，备份旧程序、数据库、配置和配方，然后仅更新主程序、`_internal` 和版本元数据。
5. 更新后检查数据库、配置和配方的 SHA256 未改变，保存升级结果。始终从原现场目录启动软件，原快捷方式继续有效。

备份位置为原现场目录的 `update_backups/时间_随机编号/`，包含升级前程序和现场数据。正常升级不会使用新版附带的数据库、人员信息、配方或配置覆盖现场数据。失败时尝试恢复旧程序；保留错误信息及备份，确认原因后再操作。首次启动新版可能进行数据库表结构兼容升级，这是应用的正常迁移，与升级脚本覆盖数据库不同。

此工具不支持链接目录，不负责搬迁数据目录。首次部署新工位仍使用完整安装目录；已有工位请走升级入口，不要直接覆盖或打开另一套初始数据库。软件应在整个升级过程中保持关闭。

## 验证边界

使用隔离数据库验证了40次测试后刷新及重开仍保留40条记录、清零审计事务回滚、异常归零追溯。使用隔离文件夹实际运行 Windows 升级脚本，验证程序更新、现场数据字节不变、备份生成，以及校验失败/源目标相同时拒绝更新。未修改现场生产数据库，也未在远端工位安装。
