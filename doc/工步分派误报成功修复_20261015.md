# 工步分派误报成功修复

对应框架流程 F11–F13，检查子工步分派、设备控制返回和最终判定。

## 本次确认问题

1. 旧式 SET_INSTRUMENT / READ_INSTRUMENT 引用未知设备，或引用已经没有驱动的 AFE 等设备时，可能没有执行任何操作却保留 success=True。在“不判断”测试项中可继续形成整项成功。
2. EASY320 旧式控制参数为空时循环不执行，仍报告成功；含非法后续通道时，前面的继电器可能已动作；宽松数字提取还可能把小数或文本误当通道。
3. 旧式模拟器读取分支只比较大于等于0，正无穷和布尔值可能被当成成功读数。
4. 旧式工步异常只写日志，返回结果可能为空，界面不易辨认失败原因。

## 修复

- 未实现的控制或读取明确报错，缺少实际驱动不再通过。
- EASY320 在发送前校验整份正整数通道列表及地址范围，保持旧配方1起始的编号含义；闭合过程中收到取消后不再闭合后续通道。
- 模拟器读取使用统一有限数值校验。
- 执行异常保留明确的 FAIL 和错误原因。

## 验证

新增 tests/test_dispatch_fail_closed.py。先复现未知仪器返回True，再覆盖未知设备、无驱动设备、空/非法通道、有效旧通道映射、取消和无效测量。另有完整引擎到临时SQLite的测试，验证“不判断”项目中的未知控制仍必须产生NG，界面完成信号不能为成功。

全量回归：712 passed、244 subtests passed，耗时31.81秒；修改文件静态检查通过。测试使用模拟设备，未控制真实继电器或仪器，未打包或推送。
