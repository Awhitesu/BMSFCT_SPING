# Qt原生崩溃：复现、修复与验证

## 已取得的证据

这次处理没有将“再次运行通过”作为结案依据。

1. 增加独立进程压力工具，逐项记录测试开始和结束。再次捕获到 Windows `0xC0000005`（进程退出码3221225477），最后运行的测试为 `test_preparation_is_async_and_cancel_does_not_start_run`，与先前异常的位置相同。日志：`logs/qt_fixed_20261015/run_000.log`。
2. 将前一个PLC任务测试和该准备测试连续执行，能在若干轮内再次触发访问异常；使用Microsoft官方ProcDump取得两份原生转储，位于 `logs/qt_native_capture/`。转储中的异常地址为0，栈内存可见Shiboken的 `Sbk_GetPyOverride`、QObject/QWidget析构等地址。此处只是转储线索，未将原始栈内存扫描冒充完整符号化调用栈。
3. 核对发现测试清理仍使用 `not thread.isRunning()` 等待后释放页面。前轮已证明：`isRunning()==False`时，原生线程仍可能尚未退出，`wait(0)`仍返回False。仅修复生产窗口关闭检查，没有修复这些测试清理路径，所以先前多次通过仍有漏检。
4. 另用受控时序验证共用任务层：阻塞后台结果信号的直接连接回调，在GUI已收到结果时释放页面引用。原实现的队列参数仍持有页面，返回后台槽时可能释放页面及其子线程，测试进程异常退出；修复后页面在GUI线程销毁，后台线程正常退出。
5. 曾单独关闭自动循环垃圾回收试验，仍然崩溃。因此没有以关闭GC作为修复，没有引入无限期不回收内存的做法。

以上证据确认了对象和线程寿命管理中的竞态，不能据此宣称历史上所有原生崩溃都有同一个原因。

## 源码修复

### DeviceTask共用任务层

- 请求信号改为无参数，不再让Qt队列参数持有页面闭包。
- 任务闭包由GUI侧运行容器保留，最后一个引用在GUI线程释放；后台槽在发出结果前移除局部引用。
- QThread由应用级运行容器持有，页面销毁不直接销毁正在执行或收尾的QThread。
- 页面删除时请求线程退出，以GUI定时器执行非阻塞的 `wait(0)` 检查，确认原生退出后才回收容器。
- 关闭后忽略页面回调；结果回调触发下一任务时，上一任务的清理不会清掉新任务引用。

覆盖硬件连接、初始化、PLC、测试准备及使用DeviceTask的调试操作。

### 单次仪器线程及其余退出路径

- MeterTask增加应用级寿命登记，原生退出前继续持有线程和任务闭包，之后在GUI线程清理。覆盖万用表、信号发生器、示波器、IT6333B、硬件管理和模拟器批量操作。
- 相关调试页的显式shutdown不再因 `isRunning()==False` 而跳过join。
- 主窗口统一退出扫描纳入应用级容器及已被页面替换的单次任务，避免漏等旧线程。
- UDS及模拟器回读线程在替换前用 `wait(0)`确认上一线程退出。
- 修正测试页面及自检对话框的清理条件，避免测试自身在后台尚未退出时释放Qt对象。
- 保留此前生产主窗口、引擎、MES和启动自检的原生退出检查。

Qt明确要求GUI对象在主线程使用，跨线程销毁须遵守对象所属线程的生命周期规则：[Threads and QObjects](https://doc.qt.io/qtforpython-6.10/overviews/qtdoc-threads-qobject.html)。

## 可重复验证

新增 `tests/test_device_task_lifetime.py`，包含7项回归：

- 页面最后引用释放的独立进程复现；
- 闭包最后引用在GUI线程释放；
- 通信期间直接删除页面；
- 完成回调立即启动下一任务；
- 人为阻塞原生线程收尾，确认容器不会提前销毁；
- MeterTask在原生退出前保留任务引用，退出后在GUI清理。
- 主窗口退出时等待已从页面替换下来的任务。

PLC→测试准备压力流程修复后两次各连续300轮通过，其中最终日志为 `logs/qt_preparation_fixed_300.log`。修复期间8轮完整回归全部通过（前两轮533项，增加原生退出用例后的6轮535项；均含244项子测试），日志为 `logs/qt_join_fixed_20261015/`。最终版本结果记录如下。

- 最终版本连续3轮完整回归：每轮536项测试、244项子测试全部通过，进程退出码均为0，日志 `logs/qt_final_20261015/run_000.log` 至 `run_002.log`。
- 修改涉及的源码、回归测试和压力工具静态检查通过。
- 这是对已复现生命周期竞态的修复和验证；不将有限次数的压力测试等同于排除了所有未来的原生异常。
