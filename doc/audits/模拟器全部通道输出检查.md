# 电池模拟器全部通道输出检查

截图中的CH78按24通道固定编号对应第4台CH6。仅凭显示0.0000V无法判断是漏设、输出关闭、限流/保护、负载问题还是通信响应异常。

此次修改：

- 每通道设置电压后执行 `SOUR<n>:VOLT?`，与目标比较（容差0.001V），最多三次设置/确认。这里只校验设备保存的设定值，不代表实际输出电压已达标。
- 输出控制执行 `OUTP<n>:ONOFF?` 校验，非法或空响应不能判为关闭成功。
- 单通道及全部通道共用串行通讯锁；使用sendall发送完整命令，并按换行符接收完整响应。查询超时后断开连接，避免后续读到错位响应；清理缓冲区遇到EOF退出，避免死循环。
- 自动化的全部设压/输出操作不再跳过未连接的启用设备；按实际配置通道数逐路执行，并记录失败设备/通道。
- 调试页批量失败提示包含全局CH号、设备序号、本地CH号及错误。全部开启后自动读取实测电压、设定值及输出状态。
- 回读表显示实际测量值；关闭的通道标注“输出关闭”。开启状态下实测与设定差值超过0.05V标为异常；异常通道列在完成提示，详情在单元格提示和控制台日志中。
- 0.05V为调试提示阈值，不替代测试配方的正式判定条件，不会自动调整限流、清除保护或重开输出。

建议复测：使用“设压并全部开启”，完成回读后查看CH78的设定值、输出状态、实测值。若设定正确且输出开启但实测仍为0，请核对该通道端子、负载和设备保护状态。

命令依据：[NGI N83624官方SCPI编程指南](https://ngitech.oss-cn-hangzhou.aliyuncs.com/NGI/N83624%20Series%20Programming%20Guide-SCPI%20Protocol.pdf)，SOURce电压及OUTPut命令章节。

## 批量提速

整套设压改为每台设备一次 `SOUR:VOLT value(@channels)` 写入，随后将所有逐通道设定值查询合并发送，按完整响应逐条校验。独立模拟器并行操作，同一模拟器内仍串行锁定。正常批量路径取消每通道50ms固定等待，只有异常通道走单独重试。

全部输出及“设压并全部开启”同样按设备批量并行执行；实测电压、设定值、输出状态回读分别合并查询，各设备并行。界面后台执行，并显示设置与校验的实际耗时。自动化的整套设压和输出控制使用相同批量逻辑。

批量请求合并发送不取消逐通道校验；缺失、非法或未匹配的响应不会视为成功。实际耗时及固件对连续查询的支持仍需实物复测，不承诺固定毫秒数。
