# CANFDNET-400U 波特率与终端电阻测试

2026-10-19，192.168.1.106:8000，项目实际 ZLGNetBus 驱动与官方 x64 SDK。四通道基线由用户提供：500 kbit/s 仲裁、2 Mbit/s 数据、终端电阻开启。基线没有通过设备配置读取接口核验。

## 发现和修复

旧调用把 apply_dynamic_data 的 value 传成 c_char_p(b'0' / b'1')。本机 SDK 附带的 C 示例传入 int 变量的地址。现已将单通道及四通道两处应用调用修正为 32 位无符号整数指针，0 表示临时配置，1 表示持久配置。

旧调用实际循环四轮后，在第五轮 CH1 添加 USERES 时返回 0；同一连接继续添加恢复配置也返回 0。关闭并重新打开后，恢复基线请求被接受。记录保留在 run1，包括 reconnect_restore.json。不能仅凭此现象断言 SDK 内部缓存的具体实现，也不能确认旧错误传参是否影响过持久配置。

修正后 run2 的 20 组配置操作全部成功，随后扩大为 run3 的 108 组，全部成功。同一连接内未再出现重复操作后拒绝提交的问题。

## 最终测试矩阵

- 四通道独立参数组合：100 轮，每轮逐通道提交、应用，共 400 个通道配置。
- 仲裁速率覆盖：50、100、125、250、500、800、1000 kbit/s。
- 数据速率覆盖：100、125、250、500、800 kbit/s，1、2、4、5 Mbit/s。
- 四个通道的终端电阻交替开、关。
- 单通道入口：CH1～CH4 各测试关闭、开启，共 8 组。
- 每组配置后做 3 次空闲接收轮询，没有异常，没有收到外部报文。
- 最后另执行四通道基线恢复，接口全部接受，随后关闭测试连接。

最终 108 组对应 408 个通道配置操作；加 4 个恢复操作，总计 412 次应用调用。此计数不能当作 412 次物理回读确认。

| 操作 | 平均耗时 | 最大耗时 |
| --- | ---: | ---: |
| 四通道提交并应用 | 423.1 ms | 431.5 ms |
| 单通道提交并应用 | 104.8 ms | 105.9 ms |

最终逐条记录包含 2052 次 SDK 调用，返回值全部为 1；其中 412 次应用参数全部为整数 0。

12 项相关软件回归通过，增加了应用参数为 c_uint 类型、临时值 0 和持久值 1 的断言。单元测试中的持久值检查使用模拟接口，没有对真实设备做持久化测试。

## 验证边界

本次验证 SDK 接受配置请求、重复调用稳定性和客户端调用耗时。没有配置回读接口、总线对端或电阻实测，因此不能证明物理波特率、采样点、120 Ω 阻值及开关电路已验收。没有发送 CAN/CANFD 报文，未验证不同波特率下的实际收发或 UDS。

修正后两轮测试及恢复均传入临时配置值 0。恢复请求为用户提供的 500K / 2M / 电阻开启，未进行配置回读，未验证掉电重启后的保存状态。

官方配置工具自动化组件不可用，官方在线接口文档站连接超时；没有把本地配方参数当作设备实际回读结果。

源码已修复，现有打包 EXE 未更新；正在运行的旧进程也需要重启加载新代码。
