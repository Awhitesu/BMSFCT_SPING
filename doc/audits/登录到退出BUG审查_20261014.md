# 登录到退出 BUG 审查

日期：2026-10-14。范围：启动入口、登录与权限、自检、首页与 PLC、配方执行、设备管理、数据记录、调试任务和退出路径。

本次只分析，不修改功能代码、不继续仓库迁移、不打包、不操作现场仪器。验证使用临时数据库、模拟驱动及无界面 Qt；现有生产配置和数据库未参与故障注入。

## 总体结论

现有 338 项测试及 244 项子测试全部通过，主程序静态检查通过，但仍存在测试没有覆盖的错误路径。最高优先级是测量误判和输出关闭范围，其次是运行时配方一致性、初始化生命周期及记录可靠性。

下表中的“复现”表示实际执行过隔离验证；“源码确认”表示路径或缺失保护能从源码确认，但未进行实机或并发故障试验。“P0”应优先处理，“P1”属于可靠性问题，“P2”属于显示、交互或追溯问题。

## P0：误判与输出保护

### 1. 无效数值、空值可以判 PASS【复现】

位置：`core/engine.py:405`、`:1887`、`:1902`。

数值测试项设置上下限 0～1，结果分别传入 None、float('nan')、'ERROR'，三种均得到 PASS：

- None 没有进入数值比较，默认 is_pass 保持 True。
- NaN 与上下限比较均为 False，因此未被判 NG。
- ERROR 被正则提取为 0，恰好落在范围内。

影响：旧数值路径的数据缺失或设备错误文本可能被当作合格；新的设备工步已做有限值检查，但主引擎仍接受旧路径和直接返回值。

建议：判定前必须确认有效、有限的数值；空值、无穷值、NaN、通信错误应成为明确的 ERROR/NG，不能默认为 0。控制结果与测量结果分开处理。

### 2. 实测异常可能被替换成合格值【源码确认，配置条件触发】

位置：`core/engine.py:630`、`:653`、`:827`。

CSC 特定路径会把异常相邻电芯改为 2.499V，另一分支含随机补偿；NTC 特定异常路径会使用随机的 24/25℃。这些替换值进入后续结果与判定。

影响：开启对应功能时，原始异常值可能被补偿值覆盖，产品缺陷与测量噪声不能可靠区分。

建议：保存 raw/derived 两组值；生产判定使用明确批准的计算规则。随机值仅允许用于显式仿真，不能混入实测判定。

### 3. 停止只关闭模拟器 CH1，其他通道及板卡未纳入【复现＋源码确认】

位置：`devices/manager.py:417`、`:429`。

safe_shutdown_outputs 使用测试通道号查找一个电池通道。当前单测试通道为 1，模拟验证实际只调用关闭 CH1；整套设备可能已开启 CH1～144。RN 板卡没有纳入该清理方法。

影响：操作员按停止后，其他模拟电池通道及需要释放的板卡输出可能继续保持。

建议：按本次运行占用的实际输出清单关闭，回读确认并报告未关闭项。用户指定 DUT 供电由专用设备负责，因此应区分测试停止和全机急停策略，不能简单扩大为无条件关闭所有供电设备。

## P1：启动、执行、记录与退出

### 4. 测试中允许切换配方【复现】

位置：`ui/tabs/overview_tab.py:665`、`:696`、`:743`。

is_testing=True 时，配方选择框仍可用；加载另一个配方会替换当前名称和树。原 worker 继续执行旧配方，后续信号按索引更新新树。通过用户选择路径还会下发新的 PLC 配方号。

影响：页面显示、PLC 配方与实际执行不一致，结果可能显示到错误项目上。

建议：运行及停止收尾期间禁止换配方，或者将修改明确作为下一次运行配置；执行和显示均绑定不可变的本次运行快照。

### 5. 自检返回 False 仍显示“全部通过”【复现】

位置：`ui/dialogs/startup_dialog.py:128`、`:139`。

_on_check_finished 未使用 success，只统计状态列表中“离线”数量。传入 False、状态列表为空时，会显示“硬件自检全部通过”，并安排自动进入系统。

建议：同时检查初始化结果、预期设备集合与错误信息；False 或初始化异常必须明确失败，不能靠“没有离线项”推断成功。

### 6. 自检过程中退出，没有可靠收尾初始化线程【源码确认】

位置：`ui/dialogs/startup_dialog.py:86`、`:94`；`ui/main_window.py:64`。

退出按钮直接 reject；窗口标志也没有真正拦截 Escape。InitWorker 没有取消令牌或退出等待，主窗口取消路径随后断开设备并退出。

影响：初始化和断开可能同时操作驱动；QThread 仍运行时销毁对话框也存在进程异常退出风险。此风险未用现场设备触发验证。

建议：退出先请求取消，等初始化操作结束再释放驱动；使用线程结束信号管理对象生命周期，并禁止重试与旧线程重叠。

### 7. 普通操作员不能点击停止【源码确认】

位置：`ui/main_window.py:305`。

开始测试对操作员开放，但停止按钮仅管理员可用。测试异常时，操作员必须切换账号或依赖 PLC 才能停止。

建议：普通测试停止对当前操作员开放；配置、统计清零、账户管理仍保留权限要求。软件停止不能替代物理急停。

### 8. 小写 admin 被授予管理员角色【复现】

位置：`data/db_manager.py:432`、`:503`；`ui/main_window.py:295`。

可以创建 username='admin'、数据库 role='operator' 的账户；get_user_role 因 upper()=='ADMIN' 返回 admin。UI 也按同样条件额外放行。

建议：保留用户名大小写规则并统一规范；禁止与保留管理员名称冲突的新增/重命名；授权读取实际角色，不用显示名称推断身份。

### 9. 切配方与启动前硬件配置仍同步执行通信【源码确认】

位置：`ui/tabs/overview_tab.py:750`、`:956`。

PLC 配方同步在界面线程执行 connect/write/read；开始测试的 CAN 应用也同步 disconnect/configure/connect。慢响应或断网会阻塞界面。

建议：使用可取消后台任务，将状态分为“准备中、运行中、收尾中”；准备完成前禁用重复开始。停止入口异步化并没有覆盖这两条路径。

### 10. 自检没有覆盖全部已启用设备【源码确认】

位置：`devices/manager.py:268`、`:332`。

RN 板卡没有进入全量初始化或状态列表；init_all_devices 在没有抛异常时直接返回 True，没有汇总 connect 返回值。因此“全部通过”不能证明所有已配置板卡可用。

建议：按本次配方需要的设备做预检，区分未启用、未检查、离线、检查通过，避免所有设备都强制连接影响启动速度。

### 11. 明细写入失败后主记录仍为 PASS【复现】

位置：`data/db_manager.py:176`、`:200`、`:237`；`core/engine.py:338`。

临时数据库模拟明细 INSERT 失败，随后 finish_test 成功；实际结果为主表 PASS、明细 0 条。异步错误只打印，不传回执行引擎。主记录完成的 FIFO 等待不等于所有前序写入成功。

建议：运行级记录持久化状态、错误汇总及 flush 确认；“测试通过”与“记录保存失败”分别显示，禁止静默生成缺失结果的正常报告。

### 12. 调试任务关闭仍可无限等待【源码确认】

位置：`ui/device_task.py:56`；`ui/tabs/hardware_config_tab.py:366`；`ui/tabs/multimeter_tab.py:192`；`ui/main_window.py:213`。

主窗口依次调用调试页 shutdown；多处 QThread.wait 没有时限。设备操作慢或未返回时，关闭窗口的界面线程会等待。

建议：将调试任务也纳入异步关闭流程，有取消、协议截止时间和明确的未完成提示；不能强行销毁仍在运行的线程。

### 13. 系统配置不是原子保存【源码确认】

位置：`data/db_manager.py:362`、`:379`。

配置文件直接以 w 模式截断写入，没有原子替换或写入互斥；读取失败又返回空配置。写入中断或并发读取可能导致恢复为默认配置/丢失现场设置。

建议：临时文件写入、刷盘、原子替换、配置备份及锁；读取异常应告警，不能静默等同首次运行。

### 14. 密码明文保存且缺少修改现有密码入口【源码确认】

位置：`data/db_manager.py:104`、`:448`；`ui/dialogs/user_account_dialog.py:102`。

密码以明文保存并直接比较，初始化包含固定默认管理员密码。当前账号弹窗提供切换、删除和新增，没有现有账户改密入口。

建议：密码带盐哈希、兼容迁移、首次管理员改密、改密入口。此项是账户保护缺口，与大小写角色错误分开处理。

## P2：显示、命令与追溯

### 15. 旧配方同步工步在执行与显示中索引不同【复现】

位置：`ui/tabs/overview_tab.py:710`、`:1071`；`core/single_channel_recipe.py:8`。

首页直接显示原 JSON，执行引擎会过滤同步工步。隔离示例：首页第一个子节点为 barrier，实际第一个执行动作为 measure。结果按 sub_idx 回填时会填到旧屏障行。

建议：显示和执行采用同一份适配后的配方或按 step_id 回填。

### 16. 旧数字字符串解析丢失负号与科学计数法【复现】

位置：`core/engine.py:405`。

实际 -10 被解析为 10；1e-3 被解析为 1。已是 float 的新测量值不受此正则问题影响，旧格式字符串仍受影响。

建议：统一数值与单位解析，完整支持整数符号、科学计数法，拒绝从错误文本中提取任意数字。此问题会影响判定，修复应与 P0 的数值有效性检查一起进行。

### 17. PLC 清零无确认，连续同值命令可能漏消费【源码确认，协议条件触发】

位置：`ui/tabs/overview_tab.py:1037`。

清零另开线程且不检查 write 返回值；_last_plc_signal 要等读到 0 才解除同值去重。若两个相同命令之间的 0 未被轮询采到，第二个命令可能被忽略。

建议：与 PLC 明确握手状态及确认规则，记录清零失败，必要时使用命令序号；不要仅依赖采到一次 0。

### 18. 首页连接工步信号晚于启动线程【源码确认，时序条件触发】

位置：`core/engine.py:2099`；`ui/tabs/overview_tab.py:942`。

engine 启动线程后返回，首页再连接 step_started/sub_step_finished/step_finished。快速首步可能先发信号，首页漏掉初始显示。内部数据库/结果监听已连接，因此这里主要影响界面而非必然丢记录。

建议：先连接统一引擎转发信号再启动，或在绑定后按 worker 的结果快照恢复状态。

### 19. 测试中切换账号会改变后续 MES 使用的操作员【源码确认】

位置：`core/engine.py:1719`；`ui/main_window.py:319`；`core/user_session.py`。

MES 工步读取全局当前用户，而执行上下文没有冻结启动操作员。运行期间允许切换账号，同一次运行可能使用不同身份。

建议：记录本次运行启动操作员；账户切换只影响新运行，或明确记录变更事件。

## 修复建议顺序

1. 数值判定与原始值保护；模拟器及板卡停止输出策略。
2. 运行时配方冻结、启动自检成功/失败判断、初始化取消和线程生命周期。
3. 权限与普通停止、记录失败反馈、配置原子保存、后台准备与异步退出。
4. 页面索引统一、PLC 握手、信号绑定顺序和操作员快照。

- 真实仪器断网、恢复、物理输出关闭及 PLC 时序尚未现场验证。
- 本报告没有宣称逐条供应商 SDK 或每一种物理设备故障均已测试；涉及动态调用及实机时序的问题以标注的验证状态为准。
