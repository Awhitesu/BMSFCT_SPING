# UDS 2E 三字段写入流程检查

## 功能边界

三字段写入仍是独立工步，只负责生成 DATA，不另写一套 UDS 协议。不自动切换会话、不执行 DLL 解锁；需要时由前面的标准 UDS 工步完成。

`固定ASCII + 执行当天YYMMDD + 本次条码指定片段 → 2E + DID + DATA → 标准UDS执行分支 → UDSClient → ISOTPTransport → PCAN/ZLG驱动 → 肯定响应及DID校验 → 输出实际写入的ASCII，保存主板序列号变量`

## 调用文件

| 环节 | 文件及作用 |
| --- | --- |
| 编辑和在线调试 | ui/widgets/uds_field_write_form.py：输入、预览、扫码、发送快照 |
| DATA生成 | core/uds_field_write.py：校验、条码截取、日期、生成标准2E请求 |
| 共用通信控件 | ui/widgets/uds_transport_settings.py：标准UDS与三字段共用帧格式、padding、BS、STmin、P2*控件 |
| 共用在线保护 | ui/widgets/uds_online.py：连接、配方参数、忙状态检查；锁定和恢复编辑控件 |
| 执行 | core/engine.py：将三字段请求编译后交给标准UDS分支 |
| 协议和驱动 | devices/uds_client.py、devices/pcan_fd_driver.py、devices/can_channel_view.py |

## 已发现并处理的问题

| 问题 | 处理 |
| --- | --- |
| 三字段没有标准UDS的高级传输参数入口 | 两者共用同一套控件和校验；三字段参数经UDSCFG64进入同一执行路径 |
| 在线抓取时仍可修改字段或切换设备、物理通道 | 冻结输入与导航，完成后恢复原有启用状态 |
| 预览和实际发送分别取日期，跨日期时存在变化窗口 | 在线抓取开始时生成单次时间和条码快照，预览及发送使用同一快照 |
| 在线连接只比较设备品牌，未核对配方波特率和帧模式 | 标准UDS与三字段统一检查本地已应用参数；不一致时不发送 |
| 任务未启动时控件可能一直禁用 | 任务拒绝启动时恢复状态并明确记录未发送 |
| 关闭窗口没有主动关闭该任务的回调 | 取消并begin_shutdown，不等待线程阻塞界面 |
| 预览没有分解三个字段和长度 | 分别显示固定字段、日期、条码片段、最终ASCII、完整PDU和长度 |
| 三字段顶部设备配置占用过多 | 与标准UDS共用紧凑概要栏，可展开设备/CAN通道配置 |

成功后才发布主板序列号变量；失败时清除旧值。没有增加写入后自动22读回：6E+DID确认写请求成功，不等于已额外读回验证。需要读回校验时继续使用后续标准UDS读取工步及变量比较。

## 兼容及参数说明

- 未设置高级参数的旧配方维持原默认行为，包括原先的P2*默认计算；不会静默修改旧工步。
- 展开高级参数并勾选“启用本步UDS通信高级参数”后，参数保存到本工步，和标准UDS使用相同校验及传输实现。显式启用也可保存默认数值（例如P2*=5000ms），不会因数值恰好等于默认而丢失设置。通信参数不在工步间暗中继承。
- 接收流控BS/STmin描述本机接收多帧响应时发出的FC；写入请求的CF发送节奏仍服从ECU返回的FC，不能把本机接收STmin当成强制请求发送间隔。
- CAN设备、物理通道和波特率跟随配方。在线调试不隐式重新连接、切换设备或重设波特率。
- 条码起始位置从1计数，截取长度0代表到末尾；越界、非ASCII、超长、相同收发ID及无效高级设置均在实际请求前失败。

## 验证与尚未确认事项

测试包含短/长PDU、Classic/FD/FD+BRS、默认及自定义padding/扩展帧、逐帧一致性、NRC及DID错误、变量清理、关闭与取消、输入冻结、任务拒绝启动和配方参数不一致。

这些是仿真和回归验证，未向BMS执行真实2E写入。现场PCAN BUS-OFF尚未复现，不能将本轮修复认定为现场根因已经解决。仍需故障当时的配方模式、仲裁/数据波特率、请求/响应及错误帧记录。
