# UDS 响应选区与最终输出

操作顺序：通讯参数 → 安全 DLL（按需）→ 服务与发送序列 → 数据解析。

1. 在发送序列中配置请求和解锁步骤，勾选要作为最终输出的普通请求行。
2. 列表发送后，实际肯定响应按序号保存到各行。进入数据解析时自动载入最终输出行的响应；其他行后续收到的响应不会覆盖它。也可选中行立即发送／在线抓取，或手动输入完整响应样本。
3. “期望响应／实际响应样本”用于生成方块。发送列表的“响应前缀校验”仍然可选，二者独立；抓取样本不会把变化的 DATA 强制变成固定 HEX 校验。
4. 拖选 DATA 字节自动更新起始偏移和长度；用快捷操作选择 ASCII、数值计算或公式。手动输入偏移、长度仍然可用。
5. 保存修改，再确认指令。运行时使用当次真实响应和保存的解析规则，工步输出最终输出行的解析值，而不是拼接原始报文。

解析方块接收已重组的 UDS PDU，不包含 CAN 长度、ISO-TP 的单帧／首帧／连续帧头。例如 `62 F1 90 41 42 43`，偏移 0 是 `62`，偏移 3 起的三个字节解析 ASCII 为 `ABC`。

完整 UDS 长度单独显示在响应样本旁，包含服务号、DID、DATA，不含传输头和填充。首帧 `10…`、连续帧 `21～2F` 和流控 `30…` 由通讯层处理；不会作为 DATA，也不会虚构一个长度字节插入响应、改变现有偏移。

响应样本随行保存，重排和重新打开仍可调整选区。它只辅助编辑，运行时不会用样本替代真实响应。取消“跟随在线抓取选区更新期望结果”可自行修改或清空解析后期望值；清空后不做额外的解析结果相等校验。

写入 `2E 1E 5E ...` 的肯定响应通常只有 `6E 1E 5E`，并不返回写入的数据。需要显示／确认写入内容时，应按 ECU 支持的协议追加 `22 1E 5E` 读回，并将这条读回行设为最终输出进行 ASCII 解析。

快捷操作新增“设为 HEX 输出”：选中字节按原顺序显示为大写、空格分隔的十六进制字符串，例如 `00 1A FF`。保留前导零及 `00/AA/55/FF` 字节，不做 ASCII 解码或数值换算。支持手填偏移和长度、保存规则、结果变量及最终输出。HEX 期望结果按字节比较，忽略字母大小写和字节间空格，但不忽略前导零字节。
