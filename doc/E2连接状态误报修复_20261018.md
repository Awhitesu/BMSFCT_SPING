# E2连接状态误报修复（2026-10-18）

> 本文保留第一轮修复记录。后续已补上实体E2 USB在位检测；当前实现、实测结果和验证范围以 [E2实体USB在位检测](E2实体USB在位检测_20261018.md) 为准。版本命令成功已不再让E2初始化通过。

## 原因

`RenesasE2Rfp.connect()`只执行本机`rfp-cli --version`。此前，只要版本命令正常退出，就把`is_connected`设为`True`。即使未接实体E2，这个条件也可能成立。

调试页直接使用该标志显示绿色“已连接”。硬件管理虽然已经将文字改为“工具就绪（目标未验证）”，但仍使用绿色；初始化日志也仍打印`connected`，自检完成标题可能显示“硬件自检全部通过”。这些入口没有统一区分工具可用和实体连接。

## 修改

- 新增独立`tool_ready`状态：版本检查成功只设置工具就绪，`is_connected`保持`False`。重新初始化失败和断开时清除工具就绪状态。
- E2调试页显示黄色“连接未验证”；工具未初始化时显示“工具未就绪”。提供状态说明，不再因版本检查通过或上次烧录成功显示绿色“已连接”。
- 查询按钮改为“工具状态”，明确返回本机工具及上次操作状态。历史Pass/Error标注“上次操作”，错误状态不作为查询成功显示。
- 硬件管理使用黄色“工具就绪（连接未验证）”，状态记录携带`connection_verified=False`。初始化完成提示和启动自检标题包含未验证项，不再把它算作硬件连接全部通过。
- 初始化日志改为“工具就绪；E2及目标连接未验证”。自动化查询使用`tool_ready`，避免因实体连接标志为False而重复初始化工具。
- 烧录、校验和回读仍通过实际CLI执行结果判定。回读及校验和操作检查工具就绪状态；成功启动烧录进程可建立工具可用状态，但不设置实体连接标志。
- 布局检查器同步使用E2工具就绪状态构造测试场景，不再伪造E2持续连接。

保留`query_state()`原有Ready/Busy/Pass/Error/Lost返回约定，避免改变已有自动化状态判定。旧工步名称“连接检测”仍兼容，但它只检查本机工具；日志明确说明不验证实体E2或目标连接。它不能作为硬件在位证明。

## 验证

新增`tests/test_e2_connection_status.py`，验证：

1. 没有实体硬件，仅版本检查成功时，驱动不设置已连接，硬件管理显示黄色未验证。
2. 工具文件丢失、版本命令失败或超时后，旧就绪状态被清除。
3. 上次操作为Ready、Pass或Error时，调试页均不变成已连接。
4. 初始化日志和启动自检汇总不宣称硬件连接全部通过。
5. 自动化状态查询复用就绪工具，不因`is_connected=False`重复初始化。
6. 工具状态查询明确标注未验证连接，缓存错误状态不报告查询成功。
