# 实际项目 DBC 验证

文件：乘用车平台EOL模式V4.5.5 20260921.dbc。

使用软件正式的 DBC 导入、后台解码和信号缓存模块进行内存模拟验证，没有连接现场 CAN，也没有修改生产配方。

## 结果

- 导入成功：2 个报文，444 个信号。
- 0x573 / BMS_Re_Message：8 字节，MessageNum 为分组选择信号。
- 0x673 / BMS_Send_Message：64 字节，发送节点为 BMS，BMSMessageNun 为分组选择信号。接收此报文需要 CAN FD 链路。
- 两个报文共 30 个分组，分别用原始值 0、1 编码并解码，共 60 个场景全部通过；覆盖全部 444 个信号。
- 每个场景清空旧缓存，检查后台缓存值，并按原始值 × 比例 + 偏移核对物理值。停止后监听器正确释放。

证据：logs/dbc_actual_project_20261019/summary.json。

## 测试步建议

1. 配方绑定实际 CAN FD 设备、物理通道和项目波特率，导入此 DBC。
2. 如果 BMS 需要先进入 EOL 模式或接收查询指令，先配置相应发送工步。DBC 只描述数据，导入本身不会自动发送密码、模式切换或查询命令。
3. 添加 CANDBC 交互工步，选择 BMS_Send_Message 下目标信号，使用 DBC 已换算的物理值设置判定上下限。
4. 设置超时、读取周期和数据有效期；需要本步的新数据时勾选等待新报文。
5. 分组信号只有收到对应 BMSMessageNun 的报文才会更新，不同分组不能视为同一时刻采样。

例如 CellVolt1 的分组为 6，比例为 0.001；原始值 3300 对应 3.3。SOC 的分组为 2，比例为 0.1；原始值 500 对应 50。CellTemp1 的分组为 5，偏移为 -40；原始值 65 对应 25。实际判定限值应由项目规范确定。

本次模拟覆盖原始值 0、1，不代表所有物理边界、实际收发方向、项目交互流程或真实 BMS 通信均已验证。现场仍需确认 CAN FD 仲裁/数据波特率及对应分组是否实际发送。
