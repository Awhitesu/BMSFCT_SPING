# 硬件状态与后台刷新修复

## 问题

硬件管理页原来每 1.5 秒在 GUI 线程调用设备状态汇总；汇总还读取系统配置，文件等待会影响界面事件处理。除 ZLG 参数行以外，编辑参数没有与当前驱动实例比较，IP 已改变但旧连接仍在线时，页面仍显示“已联机”。

可编辑串口下拉框原来优先读取 currentData；用户手动修改文字后，该值可能仍是旧选项，刷新接口列表或保存时会覆盖手动输入。

## 修改

- 状态读取改用独立的可复用 DeviceTask；在途时跳过后续刷新请求，隐藏页面不定时读取。不增加设备查询、连接或输出命令，仍使用驱动已有状态。GUI 线程只更新状态单元格，不重建输入控件。
- 新增 core/hardware_status.py，提取各共享驱动实例实际持有的地址、端口、波特率、启用状态，以及模拟器序号和通道数。与编辑区参数比较，覆盖电源、校准源、CAN、下载器、测量仪器及六台模拟器。
- 编辑参数与当前驱动不同显示“修改未应用”；取消当前仍启用设备显示“停用未应用”。工具提示保留运行状态和后续操作说明。ZLG 网络参数、SDK 行只显示参数是否应用，不将参数应用当作已连接。
- 后台读取失败明确显示“状态读取失败”和原因，下次读取成功恢复。使用修订号拒绝配置操作前、旧设备管理器的迟到结果。
- 参数编辑只使用内存快照，立即更新提示，不发起新的读取任务。状态文字、颜色、提示未改变时不重复赋值。
- 下拉框刷新和保存使用当前可见文本，保留手动填写串口。CA550 空配置默认值与驱动保持一致，避免未修改就提示配置差异。

## 验证

新增 tests/test_hardware_status_refresh.py：后台慢读取与请求合并、GUI 回调继续执行、编辑与停用状态、串口输入保留、失败恢复、旧管理器迟到结果、所有设备参数覆盖，以及应用配置前旧状态被丢弃。

中间版本相关专项 46 项通过，进程退出码 0，日志 logs/hardware_status_20261017_targeted/run_000.log。最终完整回归 807 项测试、244 项子测试通过，pytest 耗时 83.33 秒，进程退出码 0，未出现原生崩溃。完整日志和退出码汇总位于 logs/hardware_status_20261017_full/。
