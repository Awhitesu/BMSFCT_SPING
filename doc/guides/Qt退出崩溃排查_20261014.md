# Qt 偶发退出崩溃排查

## 复现与证据

完整测试在窗口退出事件处理中出现 Windows access violation（进程返回码 3221225477）。本次修复前重复完整测试，第 1 轮通过、第 2 轮重现；日志位于 logs/qt_full_repro_1.log。单独重复相关测试 20 轮及提高垃圾回收频率重复 6 轮均未重现，说明单次通过不能排除问题。

确认了线程生命周期的提前销毁竞态：在 QThread.finished 的直接连接回调中暂停线程收尾，可稳定观察到：

```text
isRunning() = False
wait(0) = False
旧 threads_finished() = True
```

这证明旧代码只检查 isRunning，会在线程尚未完成原生退出时放行窗口销毁。测试引擎也直接将 finished 连接到线程 deleteLater；MES 页面在收到请求结果时即清空线程引用。以上代码没有区分“逻辑工作完成”和“线程真正退出”。这个已确认的竞态与退出崩溃路径一致；未取得原生崩溃转储，无法证明它是历史访问违规的唯一成因。

## 修复

- 窗口退出检查同时要求 isRunning 为 False、wait(0) 成功。wait(0) 不阻塞界面。
- 测试引擎保留 worker/thread 映射，直到 wait(0) 成功，再释放线程并允许下一次测试。
- MES 请求完成后继续保留线程引用，确认原生退出后才销毁线程、恢复发送按钮，防止上一请求收尾时再次启动。
- 启动自检的重试、进入、取消和关闭同样检查 wait(0)，避免提前替换或释放初始化线程。

## 验证

新增 3 项确定性生命周期测试，主动延迟 finished 后的收尾，验证窗口退出检查、引擎释放和 MES 释放均不会提前放行。

修复后完整测试连续 5 轮通过；最新独立验证 391 项测试和 244 项子测试通过。静态检查无告警。重复验证日志：logs/qt_fixed_repro_0.log 至 qt_fixed_repro_4.log。

没有操作实际仪器，未打包。重复测试未复现崩溃并不代表排除了所有其他原生崩溃来源。
