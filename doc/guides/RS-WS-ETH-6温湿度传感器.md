# RS-WS-ETH-6 温湿度传感器接入

## 当前实机配置

2026-10-21 实测设备为仁科 P2 主动上传版，并非资料包名称所示的 Modbus TCP 问询版。

| 参数 | 当前配置 |
|---|---|
| 传感器 IP | 192.168.1.100 |
| 通信模式 | 主动上传（本机监听） |
| 上位机 IP／传感器的目标地址 | 192.168.1.250 |
| 上位机监听端口／传感器的目标端口 | 2404 |
| 上传节点号 | 1 |
| 实测终端地址 | 10117851 |

在“硬件管理中心”勾选“显示未启用设备”，找到“RS-WS-ETH-6 温湿度传感器”。勾选启用、选择通信模式、填写传感器 IP、端口及节点号后保存，再初始化设备。主动上传模式中，IP 用于识别上传来源，端口是电脑监听端口；节点号与 Modbus 站号并非同一概念。

“单通道／硬件独立调试 → 测量与信号 → RS-WS-ETH-6 温湿度传感器”提供启动接收、停止接收、当前温湿度、采集时间、自动刷新及日志。后台接收独立于调试页，切换页面不停止接收。自动刷新仅控制调试界面展示。

监听中不代表已取得测量值。只有校验正确且包含所选节点的实时上传帧才更新温湿度。登录、心跳和历史数据不刷新测量时间；超过 15 秒未收到实时测量、连接断开或校验失败后，当前值失效，避免把旧数据当成实时数据。网络断开后继续监听，允许设备重连。

当前电脑 IP 必须与传感器配置的目标地址一致。端口被其他软件占用时会明确报错；本程序不会抢占端口或修改设备网络、校准、继电器参数。后续换电脑时，需要在厂家配置工具中将目标地址改为新的接收电脑 IP。

## 配方读取子工步

新增子工步时选择“设备操作 → 测量仪器 → RS-WS-ETH-6 温湿度传感器”，功能动作选择“读取温度”或“读取湿度”。输出为数值，单位分别为 ℃ 和 %RH；可填写“保存到变量”，后续读取变量和公式计算可使用该键值。

需要上下限判定时，父测试项选择“数值”，按对应单位填写上下限，并在该子工步勾选“结果输出并参与判定”。温度和湿度分别判定时，建议建立两个父测试项，每项各放一个读取子工步。例如温度 15–35 ℃，相对湿度 30–70 %RH（仅为配置示例，实际范围按项目要求填写）。

“等待回读进入范围”可以配置等待上限及读取周期，读到符合范围的有效数值立即返回。主动上传模式的读取不会向设备额外发问询指令，仅使用后台最新有效上传值；读取周期不会改变设备实际上传间隔。断线、数据过期、无数据和校验失败会使工步失败，并清除本工步指定的变量旧值。

## Modbus TCP 型号

确为 Modbus TCP 版本时，可选择“Modbus TCP（主动问询）”，填写设备 IP、设备监听端口（通常 502，以设备实际配置为准）及站号。在此模式下软件主动连接设备，通过功能码 03 一次读取湿度 0x0000（40001）、温度 0x0001（40002），除以 10 换算。TCP 建连成功但寄存器响应无效，不会显示已联机。

两种模式不能混用。普通主动上传版使用 0x68 开头的厂家协议报文，需要登录、心跳和数据确认应答，不应向它发送 Modbus TCP 请求。

## 实测与回归

- 实机监听 40 秒，共收到 9 条实时温湿度数据及 1 条登录帧，数据间隔约 4.96 秒，未出现解析或校验错误；温度约 22.7 ℃，湿度 54.6–54.7 %RH。此结果验证通信及解析，不替代标准仪表的精度校准。
- 校验拆包／粘包、厂家实帧与应答、负温度编码、错误节点、校验失败、端口占用、来源 IP 筛选、断线重连、过期数据、配置保存和后台 UI 操作。
- 实帧测试向量见 `tests/test_renke_upload.py`；测试只使用本地模拟连接。
- 温湿度、硬件管理、扫码器与 UI 异步相关回归：55 项及 4 个子用例通过。
- 读取子工步经实际 `ChannelWorker` 测试引擎验证，输出温度 22.7 ℃、湿度 54.6 %RH，并分别成功写入本次测试变量。工步编辑保存／重开、父项上下限判定、范围等待与变量发现均有回归覆盖。
