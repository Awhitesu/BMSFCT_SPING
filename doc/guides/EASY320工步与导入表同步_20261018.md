# EASY320工步与导入表同步

问题根因：调试页已按Excel导入的`easy320_channels`显示，而工步编辑器仍固定生成32个CH选项，并写死前三个别名；自动化日志也使用旧别名。

本轮修改：

- 调试页和工步编辑器共用`configured_channels()`读取、校验配置。仅显示导入的点位，使用八进制DO编号及Excel名称；没有导入配置时保留原默认表。
- 工步勾选项采用单列滚动布局，避免长名称被横向挤压；每项提供完整文字提示。
- 新工步仍采用原有的一基十进制地址序号格式存储，以兼容现有配方。但保存、恢复均通过实际DO偏移映射，而不是控件行号。例如DO15的零基偏移为十进制13，工步保存14，执行写入13。
- 编辑旧工步时，按真实地址恢复勾选。若旧点位已不在导入表，页面提示缺失的DO编号，不把它勾选到其他点位。
- 自动执行在任何写入前校验全部选中点位。若当前导入表中不存在所选点位，拒绝执行，要求重新编辑。日志使用当前表中的DO及名称。
- “全部断开”只逐个断开当前导入表中的点位，不再固定批量操作32路。

没有修改现有配方文件或导入表，不迁移旧工步的实际地址，不向现场PLC发送控制命令。

回归新增`tests/test_easy320_step_import.py`：验证导入名称、稀疏DO编号、工步保存恢复、真实执行地址、缺失点位整批预校验及全部断开范围。最终完整回归见`logs/easy320_import_final_verified_20261018`。此前新增测试中构造函数关键字写错引起的普通断言失败保留在旧日志，不计为通过。
