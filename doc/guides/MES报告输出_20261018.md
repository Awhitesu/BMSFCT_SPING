# MES 测试报告

软件设置 → 测试报告与MES独立保存目录：分别设置测试报告根目录和第三方MES保存目录，均可使用本地盘或 UNC 网络共享。MES目录留空时不额外输出，不沿用报告目录。设备编号、站别名称和位号也在此填写。保存后在下一次测试开始时记录两个目录的快照；运行中不允许更改。

工步与配方配置 → 配方硬件关联：填写报告项目编号（例如 AP-DJ2403）及机种名称。项目编号留空时取配方名下划线前缀，机种留空时使用配方名称。

正常报告路径：

```
统一根目录/AP-DJ2403/2026-10-18/PASS/SCUx03DP050201B12610174596_Pass(20261018_20-39-59).xls
统一根目录/AP-DJ2403/2026-10-18/FAIL/SCUx03DP050201B12610174596_Fail(20261018_20-39-59).xls
```

日期和文件名时间取测试开始时间，执行时间取结束时间减开始时间；测试员工号取该次测试冻结的登录账号。报告为原生 BIFF8 `.xls`，无需现场安装 Excel。主表沿用参考文件的 Sheet1、六列、信息区、合并单元格、字体、颜色、列宽和行高。单位和原始版本字符串按记录保留。新记录增加原始文本字段，避免 `02`、`0113`、单字节 HEX `00` 被数值列去掉前导零；旧记录已经丢失的零不作猜测恢复。

测试报告按以上项目、日期、结果分层归档。MES使用单独的目录，例如 `D:/MES抓取/条码_Pass(YYYYMMDD_HH-MM-SS).xls`，所有项目统一直接输出到此目录，由第三方MES软件抓取；内容与归档文件逐字节一致，不需要MES递归扫描正常报告。此目录与测试前过站检查的HTTP接口URL无关。软件只负责生成文件，不配置第三方MES软件。

报告和MES副本均先完整写入临时文件，再以正式文件名原子发布，抓取端不会读到半份工作簿。不再生成 `.trace` 文件夹；执行追溯继续保存在测试数据库，报表归属及文件校验值记录在数据库的 `report_exports` 表中，用于重新导出及同名报告防覆盖。写入期间使用关闭后自动删除的临时锁，正常完成或失败后报告目录只保留 `.xls`。升级后可读取已有 `.trace` 的记录身份以兼容旧报告，不新增或更新其中的文件。MES路径写入失败时保留已保存的测试报告，并报告MES输出失败；没有自动重试队列。

同条码、同一开始秒存在不同记录时，不覆盖已有报告，新记录保存至当前 PASS/FAIL 下的 `重复记录/T记录编号_来源标识/`，文件名保持同样格式。MES目录同名冲突也放入该目录下的 `重复记录/T记录编号_来源标识/`，这种极少见情况需要抓取端递归扫描重复记录目录。重新导出同一记录沿用原路径。

未结束的 RUNNING 记录不发布报告。非正常结束的记录保留原状态文字，不伪装为 Pass；它们归入 FAIL 目录。
