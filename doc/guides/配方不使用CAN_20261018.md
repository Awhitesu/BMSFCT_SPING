# 配方不使用 CAN

在“工步与配方配置 → 配方硬件关联 → CAN卡”中选择“不使用 CAN”并保存。模式、仲裁波特率和数据波特率禁用，保存 can_config 为 {}。重新加载仍显示不使用 CAN。新建配方默认不使用 CAN，原有 PCAN 和 ZLG 配方保留绑定。

开始测试跳过 CAN 连接、断开、配置，不影响其他设备控制和已启用的 MES 过站检查。已有的 CAN 连接不会因为运行此配方被断开。硬件管理中心的全局设备启用配置独立于此功能。

保存及开始前检查可执行测试项：若包含 CAN、UDS、EOL、APP CAN 刷写操作，禁止在不使用 CAN 的情况下执行，提示具体测试项和工步。禁用/跳过的测试项不要求 CAN。APP 刷写配置查找本身不发送 CAN。工步编辑器提示未绑定卡并阻止确认 CAN 工步，UDS 在线请求也禁止发送。

针对测试 logs/no_can_targeted：40 passed；覆盖无 CAN 保存回读、参数禁用、不触碰 CAN 驱动、CAN 类工步阻止启动，并回归 ZLG 整机配置、物理通道路由、配方及 MES 启动流程。没有连接真实设备。

最终复核：logs/no_can_final 在既有 MES 后台测试的 QApplication.processEvents 阶段出现一次 Qt 原生访问冲突（退出码 0xC0000005）；相同测试组合在 logs/no_can_final_retry 中复跑 40 passed、退出码 0。此偶发原生崩溃未定位，不能据复跑通过认定已经解决。
