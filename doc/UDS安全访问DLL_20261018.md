# UDS Seed/Key DLL 安全访问

## 支持范围

ZCANPRO兼容的 GenerateKeyEx（7参数）和 ZLGKey（6参数）。DLL返回0代表计算成功，最终必须收到ECU对Key的肯定应答才能判定解锁成功。支持x86及x64 DLL，cdecl/stdcall，DLL在单独.NET Framework辅助进程中执行；主程序无需切换为32位。GenerateKeyExOpt、其他厂商自定义接口不在本次范围。

接口依据：ZCANPRO工具软件使用教程的“安全算法链接库”章节，原接口内容可见 https://gitee.com/openes/zcanpro/blob/main/doc/高级功能.md 。GenerateKeyEx接口说明另可参阅Vector官方“Diagnostics with CAPL”：https://support.vector.com/sys_attachment.do?sys_id=2163eca59750f9181245b1ece053af31&sysparm_viewer_id=4c03758d1b58f994afd085d2604bcb2d&sysparm_viewer_table=kb_knowledge 。本实现按ZCANPRO定义使用ushort seed长度，GenerateKeyEx输出长度为uint指针；ZLGKey长度为ushort输入/输出指针。不会探测调用未知签名的导出函数。

## 调试操作

单通道/硬件独立调试 → CAN调试 → UDS诊断 → 安全访问DLL：

1. 先连接正确CAN设备，在“请求与响应”配置请求/响应ID和帧类型，并按项目协议发送会话切换。
2. 勾选安全访问DLL，选择项目提供的算法DLL。选文件时仅读取PE位数，不执行算法。
3. 接口可选auto/GenerateKeyEx/ZLGKey；调用约定按供应商定义选择，常见cdecl。
4. 填Seed请求子功能，例如0x01；Key子功能自动变为0x02。Seed子功能只允许01–7D奇数。传给DLL的安全等级单独填写十进制，避免混淆UDS子功能和供应商定义的算法等级。
5. Variant、Seed附加参数没有要求可留空；Key最大长度是输出缓冲区容量，实际发送DLL返回的Key长度。
6. 点击“执行DLL安全解锁”，结果转到响应日志。解锁操作不自动重试错误Key；ECU返回NRC35/36/37时按项目规则处理，不循环尝试。

## 自动工步

编辑UDS顺序交互列表，填写同样的DLL配置后点击“添加DLL解锁到交互列表”。在列表中将其排在会话切换之后、受保护的读写请求之前。该行内部保存为 @SECURITY，DLL配置以SEC64保存到工步参数中。示例顺序：10 03 → @SECURITY → 2E F1 90 ...。

运行时Seed响应和Key发送共用请求锁；每次执行重新获取Seed，不缓存Key。Seed全零表示当前等级已经解锁，跳过DLL计算及发Key。空Seed、等级回显不符、DLL错误/超时、取消、Key否定应答均停止本列表后续请求。仅存在DLL配置不等于自动执行解锁，列表必须有明确解锁行；可按协议决定其位置及需要几次。

普通在线PDU嗅探不执行 @SECURITY，也不为其生成仿真假成功；使用专用调试按钮或运行工步。工步的外层忽略/重试策略仍由配方决定，请勿对安全解锁失败随意配置反复重试。

## DLL文件、部署与运行环境

选择DLL保存的是路径，不拷贝算法。请保留DLL所在目录及相邻依赖文件；DLL加载采用其目录与Windows默认安全搜索目录。相对路径以项目目录或EXE所在目录为根。部署到其他电脑时一并复制该目录并调整路径，不会把项目算法上传网络。

32/64位辅助程序位于 resources/seedkey。源文件 tools/seedkey_host.cs，生成脚本 tools/build_seedkey_hosts.py，打包脚本会自动构建过期辅助程序并打入资源。构建需要Windows .NET Framework C#编译器；运行需Windows .NET Framework v4。主UI不加载供应商DLL。进程隔离可防止主程序直接承受算法崩溃，但并非不可信代码沙盒。
