# infoscan FV31-2110 扫码器

硬件管理中心恢复统一表格布局：扫码器只占一行，包含启用、串口COM5、波特率115200及串口连接状态；和其他设备共用“保存设备配置”“初始化已启用设备”“断开所有连接”。连接只打开串口，不查询、不配置扫码器，也不发送TON/TOFF。默认不启用，避免首次启动抢占串口。

扫码器完整串口及扫码参数配置已移到“单设备/硬件独立调试 → 通讯与控制 → infoscan FV31-2110扫码器”，与触发、停止、原始报文和解码结果集中显示。独立调试页读取最新已保存配置，不另建串口连接；在独立调试页保存连接配置时也同步更新硬件管理中心的扫码器行。

厂家 Python / C# 示例使用115200波特率；数据位8、无校验、停止位1，无流控。2026-10-18在本机COM5实测，以115200/8N1发送厂家型号查询，收到 `06 0D 30 52 49 4E 46 54 59 50 46 56 33 58 0D`，即响应中包含 `RINFTYPFV3X`。这证明该参数能通信，不能仅凭型号查询认定条码已经识别成功。

厂家资料说明条码默认原样输出，前后缀可在Infostepper配置。建议配置CR或LF后缀后，软件结束方式选“必须回车/换行”。无后缀可以使用150ms静默分包，但串口没有原生报文边界，若字节间隔超过150ms或无分隔连续输出多条码，无法保证分界，必须配好结束符。编码默认ASCII，可选UTF-8、GB18030。设备阅读失败输出若自定义为其他可打印字符串，需在设备端改为NR或通过配方条码规则排除。

生产流程保持：点击开始 → 扫码窗口 → 自动提交串口结果 → 现有配方条码规则、设备就绪及MES校验 → 测试。窗口外不接收生产条码，不自动启动测试；键盘输入方式在未启用串口扫码时继续使用。扫码窗口打开时可选发送原始ASCII `TON`，结束发送 `TOFF`；外部触发模式可以取消此选项。

单设备/硬件独立调试 → 通讯与控制 → infoscan FV31-2110扫码器：按硬件管理中心配置连接、触发一次、停止。显示原始HEX与识别字符串，等待最多10秒，只做扫码验证，不启动生产测试、不计良率。生产和调试共用一个连接并排他使用；切走调试页停止该次扫码。

串口由DeviceManager中的共享驱动统一管理，初始化、配置切换和退出使用既有后台流程。后台接收线程读取原始字节，GUI只定时取内存队列，不循环查询设备。独立调试页连接操作也在后台执行。断开全部连接和退出均关闭扫码器；接收错误关闭端口并显示原因。串口打开仅表示端口可用，不会显示“型号已验证/扫码成功”。保存启用后，下次启动自检按统一设备初始化流程打开串口。

修改在源码，原有EXE需重新打包才包含此功能。

## AI条码样本推导输入

配方配置的“AI智能样本推导”窗口也共用同一扫码器。已启用并连接串口时，打开窗口开始接收；点击上方样本输入框后，扫码自动添加独立样本（去重），不会覆盖尚未提交的人工输入。人工输入或粘贴后仍可按回车或“添加样本”。点击下方“测试条码”框后，后续扫码填入该框并验证当前规则，不添加到样本列表；也能直接手动修改验证条码。

该弹窗可连续收取样本；软件触发模式收到条码、NR或其他完整返回后发送TOFF，异步等待100ms后再发送TON。没有任何返回时，3秒后同样停止并重新触发，避免首次未识别后再也不扫码。不得把TOFF和TON无间隔连发。使用定时器等待，不阻塞界面；外部触发模式不自动发送指令。关闭、取消或应用后同时取消所有续触发定时器，释放本次扫码，不关闭统一管理的串口。其他任务占用扫码器时不会抢占，窗口显示原因并保留人工输入；未启用或未连接时同样可人工输入。
