# 设备控制与退出优化（2026-10-17，第二批）

## 已修改

1. DG2052 调试、测试工步、初始化和停机共用控制入口，校验通道和输出参数。输出控制必须返回有效参数快照，并且输出回读与请求一致；空字典、布尔返回值和未知状态不能冒充确认。
2. 板卡调试、自动测试、停机和整套电阻设置共用 `core/board_control.py`。电阻设置要求返回值精确等于请求值（0Ω有效）；继电器核对布尔回读、配置通道数及目标状态；绝缘板明确关闭时忽略旧阻值，写0并确认关闭。
3. 控制入口拿到共享驱动锁后重新检查取消；停止后阻止后续开启，允许关闭。配置与关闭同时失败时保留两种错误。
4. 存在失联且无法确认的输出时，即使调用者允许继续清理，也不再记录“已执行安全断电”的完整成功提示，而明确记录未确认输出。
5. 退出资源清理函数只接收后台资源及独立结果容器，不直接捕获主窗口，也不从后台线程写窗口字段。界面在后台线程结束后读取错误并决定重试或退出。
6. 对部分 Qt 测试替身改用普通函数转发调用记录，避免直接把 Mock 放在 QObject 方法上；窗口关闭测试补充显式延迟销毁。这些测试改动不能被当作原生崩溃已经解决的证明。

## 测试证据与限制

- 设备控制专项：83 项测试、162 个子测试通过，3.60秒，退出码0。
- 窗口关闭单项实际连续调用50次通过，退出码0。最初尝试重复pytest节点会被去重，只有1次，不计入50次证据。
- 普通全量回归多次出现 Windows 原生访问异常，常见位置为窗口关闭测试的事件处理；另一次发生在线程原生退出期间，主线程位于电阻板界面测试。该问题尚未确定完整根因。
- 诊断性运行（每项测试后在GUI线程执行GC并处理DeferredDelete）：775项、244个子测试通过，107.72秒。它改变了回收时序，不能替代普通回归结论。
- 最后两次普通全量回归：每次775项、244个子测试通过，分别41.70秒及42.24秒，退出码均为0；未禁用GC，也未加入每项测试回收钩子。原生异常此前可复现，不能仅凭两次通过宣称根因已经消除。复验输出为 `logs/control_final_repeat_20261017.log`，两轮均保留JUnit XML。
- 另一诊断运行禁用了自动GC，只用于区分回收时序，不能作为正式验证。普通回归中的旧测试替身返回值已更新为真实驱动的返回格式，未放宽正式确认规则。
- 未连接或操作真实设备，未打包或上传GitHub。以上回读确认仅代表驱动支持的设备状态/设定值确认，不把设定值回读当成外部实测。
