# 登录到退出流程 BUG 修复记录

对应《登录到退出BUG审查_20261014.md》的 19 项发现。

## 已修复

- 测量判定拒绝空值、非有限数、错误文本；保留负号及科学计数法。CSC、NTC 保留原始测量数据，取消随机补值和异常替换。等待工步拒绝非法时长。
- 停止覆盖已连接电池模拟器的全部配置通道及板卡输出；普通停止保持被测物供电策略，紧急停止另行处理供电。清理失败明确报告。
- 测试准备、PLC 配方同步、退出清理移到后台执行；退出等待任务结束，不在界面线程等待设备通讯。
- 初始化失败不能显示全部通过；取消自检等待初始化线程安全结束。板卡纳入初始化及状态检查，连接失败汇总反馈。
- 测试期间冻结配方、操作员和设备准备参数，禁止配方切换及配置编辑；清理结束才允许重新启动。
- 操作员可以停止测试。管理员权限按数据库角色判断，取消用户名大小写捷径。
- 新密码使用带随机盐的 PBKDF2 存储；旧密码成功登录后迁移。默认管理员首次登录必须更改初始密码，增加个人密码修改入口。
- 配置采用加锁、临时文件、原子替换及备份。损坏的配置显式报错，不静默恢复默认值。
- 结果写入失败标记 RECORD_ERROR，不作为普通 PASS 或产品 NG 计数；停止路径捕获结果及清理异常。
- 界面与执行器一致过滤历史同步节点；工步信号在启动线程前连接，避免首次工步结果丢失。
- PLC 命令复位需要确认成功，同一命令复位后可以再次处理。

## 验证

- 新增 25 项故障回归测试，覆盖异常值、原始读数、密码迁移、配置写入失败、结果写入失败、取消准备、退出等待及首工步信号等场景。
- 全套：363 项测试通过，244 项子测试通过。
- Python 静态检查无告警。
- 使用临时数据库、模拟驱动及离屏 Qt 界面；没有操作实际仪器，没有打包或上传。

## 实机验证边界

硬件厂家接口调用不能强行终止；取消操作会等待当前通讯调用返回。后台执行保证界面不因主动等待而阻塞，实际耗时仍取决于设备和通讯超时。输出是否真正关闭及测量精度仍需设备现场验证。

## 第二轮检查修复

- 子工步重试前移除本次失败尝试的候选测量值，保留之前工步的有效值，避免成功重试后仍用旧失败读数判定。失败尝试仍通过原有日志和信号反馈。
- 非法测量文本保留原值，避免判定 NG 后报表却记录成 0。
- 等待时长必须为非负整数毫秒，拒绝负小数和小数被截断后意外立即完成。
- 通用仪器测量入口拒绝布尔值及缺失值，避免 True/False 被转换成 1/0。
- 准备任务未被后台接受时恢复准备状态及配方控件，避免一直停在 PREPARING。

新增 11 项回归测试；全套 374 项测试及 244 项子测试通过，Python 静态检查无告警。本轮仍未进行实机验证或打包。

## 第三轮检查修复

- 公式计算仅对实际引用的输入做严格数值校验；错误文本、缺失值、布尔值、NaN、无穷大均失败，不再转成 0。改为解析算术表达式，支持变量和 abs/round/min/max，并拒绝属性访问等非计算表达式。
- 读取变量和公式结果保留数值精度，取消在判定前固定保留两位或四位小数，避免小信号误判。
- 工步事件或测试项结果无法进入写入队列时，明确记录 RECORD_ERROR，执行输出收尾并发出测试结束信号，避免线程卡在当前工步。
- 新增 14 项回归测试；最新全套测试输出为 388 项测试及 244 项子测试通过，静态检查无告警。原 UDS 测试的读取变量预期同步改为原始数值。

仍待定位：全套测试曾两次在异步窗口退出测试的 Qt 事件处理中触发 Windows access violation；同文件单独运行、与新增测试联合运行及最新全套运行均未重现。没有证据确认根因，也不能据此认定真实应用退出流程已完全排除崩溃风险。未进行实机操作。

后续专项排查已确认并修复线程提前销毁竞态，完整测试连续 5 轮通过。详细证据、修复及边界见《Qt退出崩溃排查_20261014.md》。

## 第四轮检查修复

- MES 调试页不再依赖当前启动目录读取或写入配置。主窗口将 DBManager 传给 MES 页面，独立页面使用固定的程序配置路径。
- 统一系统配置读写至 core/system_config.py，各页面及数据库管理器按同一文件路径共用锁。保存采用读取、合并、临时文件及原子替换，避免并发保存覆盖其他设备参数。损坏配置显式失败，保留原文件。
- MES 超时拒绝 NaN、无穷大、零和负数。配置保存失败不显示成功，也不继续发起请求。
- MES 后台请求异常始终返回失败结果，避免线程缺少完成信号而一直占用发送按钮。
- 自动序列的 MES 工步改用统一配置读取；读取失败不再静默使用默认连接参数。
- 报表文件名加入 test_id，避免同条码同秒同结果的记录互相覆盖。项目目录和结果文件名过滤路径字符，避免配方名称使报表离开预期目录。

新增 10 项回归测试，覆盖并发配置保存、损坏配置保留、超时校验、MES 异常收尾及报表路径/重名。全套 401 项测试及 244 项子测试通过，静态检查无告警。未打包、未操作实际仪器。

## 第五轮检查修复：瑞萨 E2 虚假校验成功

自动测试与瑞萨调试页都存在 compare_and_diff_data(rb_bytes, rb_bytes) 调用，回读数据与自身比较，不能证明源程序与芯片内容一致。回读失败、长度不足或校验异常也未必改变下载成功状态，调试页最终 PASS 更未使用校验后的结论。

- 新增 core/renesas_verify.py，校验 HEX/S-record 记录校验和、结束记录及地址，按源文件的实际数据段回读，逐字节比较源程序和芯片数据。不对源程序空洞区域假定内容。
- 回读失败、截断、源程序无效或字节不一致均不能 PASS。临时文件在成功及失败时都清理，回读分块支持取消检查。
- 调试页将校验结果传递给最终操作状态；自动测试使用同一校验逻辑。
- 留痕记录包含源程序、回读数据和真实差异，并修正自动测试归档 SN 字段。
- 支持 HEX/MOT/S-record。RPJ 工程尚不能提取源程序字节，启用逐字节校验会明确失败；BIN 必须通过自动工步 VERIFY_ADDRESS 明确起始地址。未勾选逐字节校验时仍由原下载工具的 program/verify 返回值决定下载结果。

新增 11 项测试覆盖实际地址、匹配/不匹配、失败/截断、校验和、S-record、BIN地址、取消和最终状态传递。旧成功测试改为真实源文件基准或明确关闭逐字节校验，不再接受不存在源文件却校验成功的行为。全套 412 项测试、244 项子测试通过，静态检查无告警。未操作实机、未打包。

## 仪器控制专项检查

检查了 NGI 高压源、电池模拟器、IT6722A、IT6333B、CA550、DG2052、TBS2102B、34461A、EASY320 和 RN 板卡的控制、回读及异常入口。本轮确认并修复：

- NGI 高压源输出回读不一致仍返回 True；现在继续有限重试，未确认目标状态则失败。
- 错误队列用子串匹配判断 0，可能将 -100/100 等错误码当作成功；现在严格解析错误码为 0，并保存错误信息。清除保护操作也检查错误队列。
- 高压源空回复或错误文本可能转成 0；现在返回失败标记，拒绝非有限测量值及非法设定值。
- 高压源单次 recv 假定回复完整，发送使用 send 且忽略短写；现在按换行拼接回复并限制长度，使用 sendall。断开连接即使 shutdown 失败也尝试关闭 socket。
- IT6722A 设置后回读及输出后回读缺少覆盖全操作的锁；现在原子执行，避免其他通讯插入。串口短写明确失败。
- ITECH 数值解析接受 NaN/Infinity，IT6333B 回读检查可能漏过；现在拒绝非有限数值。
- 电池模拟器状态回读将 2/0.5 等非法值转成 True/False；现在仅接受明确状态和数值 0/1。
- 示波器资源 close 抛异常时未清空连接状态、未关闭资源管理器；现在所有资源都尝试释放，并清除连接状态。
- 自动工步将电源的失败标记 -1 视为有效读数、CA550 错误文本转成 0；现在明确失败。CA550 设定失败后不会继续开启输出，配置指令显式错误不会被后续成功覆盖。校准仪设置及回读也加完整操作锁。

新增 36 项故障回归测试；全套 448 项测试及 244 项子测试通过，静态检查无告警。未操作实际仪器、未打包。协议命令是否被各台仪器实际固件支持、输出及精度仍需现场验证，模拟测试不能替代实机确认。

## 登录自检高压源误显示连接

发现连接判定可直接复用 is_connected/socket 旧标记，且新连接对任意非空 IDN 回复都认可，没有确认高压源型号。状态页面仅显示该标记，因此存在误显示已联机的路径。

- 每次 connect 重新建立连接并查询身份；仅接受 N3618 系列身份，再查询 OUTP?，确认得到 0/1/OFF/ON 的有效回复。
- 初始化失败或抛异常时，管理器尝试断开并强制清除高压源连接标记，状态列表显示离线。自检日志包含失败原因或成功设备身份。
- 登录自检改为被动查询，不下发输出指令或清除保护状态。

新增 12 项测试验证错误型号、空/错误身份、旧连接、无效状态、分包回复和管理器离线显示；均通过。新增最后两项前全套 458 项测试及 244 项子测试通过，静态检查通过。未连接实际高压源或改变仪器输出。

## CA550 专项检查

- 原连接逻辑只要求 IDN 非空且不含大写 ERROR，可能把其他仪器、错误文本或串口回显当作 CA550。现在要求身份中存在 CA550 型号，并通过 SO? 获取有效 0/1 输出状态；查询不改变输出。
- 原握手异常可能保留打开串口，空配置或冷却期提前返回可能残留连接标记。现在连接前清理旧资源，失败统一断开并记录 last_error/identity。
- 更换串口后不再被前一个串口的失败冷却时间拦截；时间判断改为单调时钟。
- 检测串口指令短写。查询超时返回明确错误并清理连接，避免将空回复作为正常通信。
- 输出状态请求规范为 SO0/SO1，避免布尔值格式化成 SOTrue/SOFalse；控制路径对 ERROR 大小写统一处理。

新增 14 项 CA550 测试通过，全套 474 项测试和 244 项子测试通过，静态检查无告警。未变更原串口参数及源输出范围，也未操作实机输出。设备实际身份回复格式和串口通信仍需现场确认。
