# 配方CAN绑定与工步物理通道

问题：工步原有“RNCAN通道”实际上为历史逻辑通道号，PCAN单通道实现忽略该参数。ZLG发送使用连接时默认句柄，接收筛选也固定到默认通道，无法仅靠修改该字段选定CH1–CH4。

## 当前行为

- 工步编辑器从配方配置页读取当前CAN设备绑定，显示只读“PCAN_USBBUS1（配方绑定）”或“ZLG CANFDNET-400U（配方绑定）”。工步不能独立选择另一张卡。
- 新增公共“物理通道”字段，适用于CAN发送/接收/问答、EOL及UDS。可跟随配方默认通道；PCAN只提供CH1，ZLG提供CH1–CH4。配方明确禁用的ZLG通道不可选。
- 原CAN与EOL页面中的“RNCAN通道”输入框隐藏；历史CH字段继续读写兼容，新的物理通道独立保存为PCH。PCH为1–4表示明确选择，0或缺失表示跟随配方当前默认通道，避免将旧逻辑CH强行解释成物理通道。
- 新物理通道可以保存、编辑恢复；换成PCAN配方后，不合法的旧ZLG通道显示提示并在运行时拒绝，不静默转移到另一通道。

## 实际收发

使用同一共享CAN驱动的通道视图，不另建连接、不改变全局默认通道。发送帧携带真实物理通道，ZLG按该通道选择原生句柄。接收、清理历史、问答和ISO-TP/UDS绑定到相同通道，防止其他通道同ID报文误匹配；请求仍共用驱动锁。

自动化启动仍先按配方应用设备与四通道参数。在线UDS抓取入口也绑定所选物理通道；如果当前已连接的卡类型与配方不符，则拒绝使用错误卡发送。

发送监控记录保留真实接口和物理通道，不把逻辑CH当作实际来源。运行时拒绝不属于当前卡或未启用的物理通道。
