# BMS老化测试上位机 - 项目需求文档

## 1. 项目概述
本上位机软件主要用于 BMS（电池管理系统）的老化测试。软件需支持多通道并发测试，并具备灵活的“主-从”拓扑配置、扫码绑定入站、用例工步编辑以及单通道独立调试等核心功能。

## 2. 系统架构与硬件资源

### 2.1 物理架构
系统采用三层物理架构，确保高电压测试的安全性和分布式控制的灵活性：
1. **控制柜 (Centralized Control)**：包含源端设备（电源、模拟器、标准源）及 PLC 总控单元。
2. **老化功能板阵列 (Execution Layer)**：每一工位配置一块功能板（1:1），集成继电器矩阵与 CAN-TCP 网关。
3. **老化车 (Load Carriers)**：物理承载被测 BMS，共 3 台车，每台承载 20PCS，通过标准化线束连接。

### 2.2 核心资源池
- **电池模拟器（3台）**：每台负责 20 个工位，共支撑 60 个电芯电压采样通道。
- **AFE 供电电源（3台）**：为从板 AFE 芯片提供独立工作电源。
- **高压源（1台）**：提供 1500V 级直流高压，通过功能板总线接入 60 个工位。
- **标准校准源 (Yokogawa CA550)**：提供高精度 mV 级信号，用于分流器或传感器采样校准。
- **总控 PLC (EASY320)**：负责电力分配逻辑及继电器上电顺序控制。

### 2.3 共享资源与路由逻辑
本系统的电池模拟器采用“物理串联、逻辑并联”的特殊拓扑架构，软件设计必须遵循以下逻辑：
1.  **54 串总系统**：3 台模拟器（每台 18CH）通过物理串联，形成一个提供 54 串模拟单体电芯的大电池包。
2.  **工位并联**：所有 60 个测试工位（BMS 从机）在物理上都是并联在这同一组 54 串模拟单体上的。
3.  **代码路由逻辑**：
    - **配方索引**：在测试用例（Recipe）中，`CH:x` 参数指代的是这 54 串模拟电芯中的第 `x` 串，而非测试通道号。
    - **自动路由**：底层驱动 `_get_sim_and_ch(global_ch)` 中的 `global_ch` 在执行模拟器工步时，接收的是配方中的电芯索引（1~54）。
    - **映射算法**：算法 `unit_index = (global_ch - 1) // 18` 能够精确地将 1~54 号电芯映射到 3 台物理模拟器的对应通道。
    - **资源共享性**：由于 60 个通道共用这 54 串硬件，任何一个 ChannelWorker 修改 `CH:x` 的电压，都会同步改变所有通道看到的该单体电压。因此，必须通过“同步屏障”机制确保资源操作的一致性。

## 3. 核心功能需求

### 3.1 BMS 拓扑与通道管理
- **主从模式配置**：每个测试通道支持“1主多从”的模式，且必须支持灵活配置：
  - 1主0从
  - 1主1从
  - 1主2从
  - 1主3从
- **通道数量与扩展**：当前系统标准配置为 **48 通道**，软件架构设计上必须具备无缝扩展至 **60 通道** 的能力。

### 2.2 扫码绑定与语音提示工作流
在测试正式开始前，必须经过扫码流程：
- **货架码静态映射配置**：系统需在后台预先配置好【货架码】与【测试通道（1~60）】的一一匹配关系。
- **扫描货架码定位通道**：操作员首先扫描货架码，系统通过配置表自动匹配，并锁定将要入站的那个特定测试通道。
- **扫描设备码**：通道被定位锁定后，继续扫描该通道内配置的主机编码，以及相应数量的从机编码，完成该通道的全部扫码入站。
- **语音提示联动**：在弹出扫码框以及扫码操作期间，软件需连接并控制外部“语音模块”，给出相应的操作语音提示（语音模块通讯协议待后续提供）。

### 2.3 测试用例与工步管理
- **用例复用机制**：测试项目应设计为可复用的副本。用户只需编写好一次测试用例，即可下发并应用到所有通道上，极大地减少重复配置工作。
- **参数动态还原**：支持对已保存的工步进行二次编辑。系统需能解析参数字符串（如 "12.0V/2.0A"），并自动还原到 UI 编辑框中，方便用户微调。
- **高效编辑套件**：支持标准的剪贴板操作（Ctrl+C/V 复制粘贴、Delete 删除）及右键快捷克隆，极大提升配方编写效率。
- **右键快捷操作**：支持通过右键菜单快速“屏蔽/取消屏蔽”特定工步（跳过测试而不删除）、添加自定义命名前缀。屏蔽项在 UI 上以灰色显示，逻辑上自动跳过。
- **仿真运行 (Dry Run)**：支持基于虚拟硬件 (`MockDeviceManager`) 的配方逻辑仿真运行。用户可以在无硬件环境下运行完整测试流，通过实时监控窗口验证工步逻辑、延时及 NG 策略。
- **配方合法性校验**：保存配方前自动执行逻辑校验，确保所有测试项非空、参数完整，防止由于配置疏忽导致的无效测试。
- **全局参数批量修改**：支持跨设备、跨工步的参数批量替换、统一设置或策略修改（如一键修改所有设备的失败处理策略）。

### 2.4 调试与设备管理
- **单通道/设备独立调试**：软件需提供专门的调试功能界面，便于工程师脱离主测试流程，单独对某个通道或某个特定设备（如指定的BMS或测试机）进行硬件校验、通信报文收发测试及手动参数下发。
- **全局设备配置**：需具备一个全局的硬件配置中心（界面），专门用于设置系统涉及的所有外设参数（如扫码枪、语音模块COM口、所有测试仪器的IP或波特率等）。

### 2.5 数据记录与存储
- **全通道数据追踪**：测试运行期间，48~60 个通道的测试记录必须独立且实时保存。
- **双轨存储机制**：
  - **本地数据库**：建立本地数据库（如 SQLite）对各个测试工步数据进行结构化存储，便于日后条件查询。
  - **本地 XTML 文本**：每次测试结束后，生成对应通道的本地 XTML 格式文本文件，作为原始数据备份或外部系统导入使用。

### 3.7 系统控制策略 (Software Strategy)

#### 3.7.1 电源管理：分级顺序启动
- **防浪涌逻辑**：PLC 接收上位机指令，按照预设的时间间隔（如 500ms）分批次闭合老化功能板的供电继电器，防止大功率瞬间启动导致系统崩溃。
- **逻辑自检**：上电后自动进行 TCP 握手，确认 60 个节点在线后方可开启测试。

#### 3.7.2 同步屏障机制 (Synchronization Barrier)
- **步段同步**：针对高压源、模拟器等全局共用资源，采用“同步锁”控制。
- **参数互斥**：只有当 60 个通道在当前参数下的测试项全部完成后，才允许更改共用设备参数。
- **采样挂起**：参数切换期间（如电压升压），所有通道自动挂起采样对标，待稳定后由上位机发送“释放信号”同步恢复。

#### 3.7.3 高精度校准：时分复用巡检
- **自动轮询**：在特定测试工步，上位机驱动继电器矩阵将 CA550 依次（1~60号）切入对应工位。
- **比对逻辑**：软件读取功能板与 BMS 通信数据，对比 CA550 标准值与 BMS 上报值。

#### 3.7.4 数据通讯：分布式采集与并发
- **TCP 并行处理**：上位机开启多线程或异步 IO 监听 60 个 TCP 连接，确保 60 路 CAN 报文实时落地存储。
- **异常屏蔽逻辑**：具备故障自动剔除功能，某一工位硬件损坏或中断不影响其他工位执行。

## 3. 界面 (UI) 需求
- **整体规划**：
  - **多通道总览界面**：使用网格或卡片形式实时展示 48~60 个通道的状态（空闲、测试中、异常、通过等）。
  - **扫码入站弹窗**：操作员联动语音的扫码界面，包含当前扫码进度提示。
  - **工步/用例配置界面**：类似于组态软件的步骤添加、NG策略配置及参数调整界面。
  - **系统硬件配置界面**：统一管理所有连接设备通讯参数和本地环境配置。
  - **详细监控窗口**：支持单通道的“开启测试”、“结束/停止测试”及“局部步骤勾选执行”功能。实时显示子工步执行日志及 PASS/NG 状态。
  - **单通道/单设备调试界面**：针对单通道和单设备，提供底层的指令下发、强制动作和报文监控界面。

## 4. 技术栈要求
- **核心框架**：Python + PySide6 (Qt for Python)
- **UI 界面**：QSS 样式驱动 + 组合式布局
- **通讯类库**：`pyserial` (串口驱动), `socket` (TCP通讯), `pymodbus` (电源通讯库)

## 5. 开发进度与已实现关键特性
- **[已实现] 动态工步解析**：支持从字符串参数中自动还原 UI 配置，实现“所见即所得”的二次编辑。
- **[已实现] 硬件安全联动**：测试执行前及执行中强制校验硬件联机状态，任何通讯中断将触发 NG/FAIL，杜绝虚假测试结果。
- **[已实现] 详细监控体系**：单通道弹窗式监控，支持启停控制、进度追踪、实时日志及详细判定项列表。
- **[已实现] 双轨数据持久化**：SQLite 结构化存储用于本地统计，XTML 文本用于原始数据存证。
- **[已实现] 高并发测试引擎架构**：引入线程池生命周期管理与“僵尸线程”托管机制，彻底解决了多通道并发启停时的底层资源竞争与崩溃问题（如 `Destroyed while running` 和死锁问题）。
- **[已实现] 底层通讯全栈可观测性**：全面升级系统日志体系。所有的硬件（电源、模拟器、CAN）在执行指令时，实时记录并输出具体的 IP/COM 信息以及收发原始报文 (TX/RX)。
- **[已实现] 高级配方编辑套件**：实现了基于 QTreeWidget 的树状配方编辑器，全面支持剪贴板操作 (Ctrl+C/V)、右键快捷屏蔽/取消屏蔽及自定义命名规范。
- **[已实现] 配方逻辑仿真系统 (Dry Run)**：开发了完善的虚拟硬件驱动层，支持脱机仿真运行测试流，大幅缩短了逻辑验证与调试周期。
- **[已实现] 自动化校验与批量编辑工具**：集成了保存前逻辑强校验机制，并提供了可视化的全局参数批量修改功能。

## 6. 关键设备协议记录

### 6.1 万瑞达/允星河 RU 系列电源 (AFE & 主机电源)
系统集成了两台 RU 系列直流电源，通讯协议均遵循《万瑞达电气 RU 电源 LAN 通讯协议-V1.4》。
- **物理连接**：以太网 TCP（默认端口 2000）。
- **通讯协议**：Modbus TCP (标准 SOCKET 帧结构)。
- **Slave ID**：默认 1。
- **寄存器**：读取电压(100), 读取电流(101), 设定电压(149), 设定电流(150), 输出开关(133)。
- **倍率处理**：1# AFE 电源(10倍率), 主机电源电压(100倍率)。

### 6.2 领图 66100 电池模拟器 (Simulator)
- **协议**：SCPI 标准指令集 (TCP/IP)。
- **核心指令**：`SOUR[ch]:VOLT <v>`, `MEAS[ch]:VOLT?`, `OUTP[ch]:STAT <1/0>`。
- **架构**：支持 4 台设备组联，每台管理 18 个物理通道。

### 6.3 NGI N3618 高压直流电源 (HV Source)
- **协议**：Modbus TCP。
- **用途**：模拟动力电池总正/总负高压。

### 6.4 CAN 总线通讯
- **硬件**：周立功 (ZLG) 或兼容的 CAN 适配器。
- **功能**：支持 CAN 报文发送、等待指定 ID 响应（交互/问答模式）。
